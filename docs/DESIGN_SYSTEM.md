# Дизайн-система «KAZANKIN ВИДЕОМОНТАЖ»

Дизайн-система сформирована на основе референсных материалов из каталога `Referens/` и строгих требований к CSS-переменным, адаптивности и примитивным лейаут-компонентам.

---

## 1. Фундаментальный принцип: Строгие CSS-переменные

## 2. Атомарные лейаут-компоненты (`shared/ui`)

Компоненты лейаута создаются в `shared/ui` и сопровождаются историями Storybook:

1. **`<Container>`**: Ограничивает контент по ширине (`max-width: var(--container-max-width)`), центрирует и задаёт безопасные боковые отступы (`24px` на десктопе, `16px` на мобильных).
2. **`<Section>`**: Блок секции с возможностью режима `fullpage` (`height: 100vh / 100dvh`, `scroll-snap-align: start`) на десктопе и безопасным `min-height: 100dvh` с внутренним скроллом на мобильных.
3. **`<Heading>`**: Заголовок с уровнями `level={1|2|3|4|5|6}`, поддержкой пропса `overline` (надзаголовок с префиксом) и `highlight` (акцентная часть текста цветом `--color-light-beige`).
4. **`<Text>`**: Текстовые параграфы и подписи с типизированными вариантами: `body`, `caption`, `lead`, `muted`.
5. **`<Block>` / `<Box>`**: Базовый блочный контейнер с пропсами отступов (`p`, `px`, `py`, `m`, `bg`, `radius`).
6. **`<Stack>`**: Flexbox-стек (вертикальный или горизонтальный) с поддержкой пропсов `direction`, `gap`, `align`, `justify`, `wrap`.
7. **`<Grid>`**: CSS Grid компонент с адаптивными колонками `cols={{ sm: 1, md: 2, lg: 3 }}` и `gap`.
8. **`<Button>`**: Кнопка действия с вариантами `primary` (бордовая), `secondary` (аутлайн на тёмном фоне), `outline-light` (на светлом фоне). Минимальная высота на тач-устройствах `44px`.
9. **`<Badge>`**: Статусный бейдж (`success`, `neutral`, `disabled`) для обозначения участия в этапах монтажа.
10. **`<StarRating>`**: 5-балльный рендер звёзд (от 1 до 5) с семантическим текстом для скринридеров (`aria-label="5 из 5 звёзд"`).

## 3. Требования к доступности (a11y) и скринридерам

- Все интерактивные элементы должны иметь видимый фокус-стиль (`:focus-visible` с цветом `--color-light-beige`).
- Скрытые от зрячих пользователей, но доступные скринридерам служебные метки оформляются через класс `.sr-only`.
- Иконки сопровождаются `aria-hidden="true"`, а содержащие их кнопки — `aria-label`.
- Для аккордеона этапов обязательно применение парных атрибутов: `aria-expanded` на кнопке триггера и `id` + `role="region"` на раскрывающемся контенте.

## 4. Адаптивность для устройств с меньшим разрешением

1. **Мобильная сетка (Breakpoints):**
   - **До 768px (Mobile):** Сетки карточек перестраиваются строго в 1 колонку. Контейнер получает боковые поля `16px`. Текстовые блоки растягиваются на 100% ширины.
   - **768px – 1023px (Tablet):** Сетки работ и отзывов перестраиваются в 2 колонки.
   - **1024px+ (Desktop):** Полноразмерная 3-колоночная сетка для работ и 2-колоночная для этапов.

2. **Мобильная навигация (Header & Drawer):**
   - На экранах `< 768px` горизонтальные ссылки навигации скрываются, отображается доступная кнопка мобильного меню (гамбургер) с тач-зоной не менее `44x44px`.
   - При открытии меню плавно выезжает боковая или полноэкранная панель (Mobile Drawer) со списком категорий и кнопкой переключения языка.
   - Фокус автоматически перемещается в открывшееся меню; закрытие осуществляется по клику на ссылку, крестик или клавишу `Escape`.

3. **Сенсорные экраны и тач-зоны:**
   - Все кликабельные элементы (кнопки, плашки аккордеона, переключатели) имеют размер не менее `44x44px` по стандарту WCAG 2.5.5 Target Size.
   - Добавлены отступы между интерактивными элементами для предотвращения случайных нажатий.

4. **Полноэкранный скролл на мобильных устройствах:**
   - Используется единица измерения `100dvh` (Dynamic Viewport Height) для учёта скрывающейся панели адреса браузера на iOS и Android.
   - Для секций, высота содержимого которых может превышать высоту экрана смартфона (например, длинный список этапов или отзывов при их раскрытии), включается безопасный режим: `min-height: 100dvh; overflow-y: auto;` — это гарантирует, что ни один элемент не окажется обрезан снизу.
