# Agent work in Kazankin project

Этот проект разрабатывает и развивает веб-сайт портфолио/лендинг для **Дмитрия Казанкина («KAZANKIN ВИДЕОМОНТАЖ»)** на основе предоставленных референсов (`Referens/`).

Управление проектом, контроль качества и ведение задач осуществляются по методологии **High Grade** (SDD — разработка от спецификаций, BDD — проверяемые поведенческие сценарии, Test-First).

Начните с [README.md](README.md) и местной инструкции [.highgrade/project/INSTRUCTIONS.md](.highgrade/project/INSTRUCTIONS.md).

<a id="актуальный-контекст-реализации"></a>

## Актуальный контекст реализации

- HG-0001 не синхронизирован с текущим UI; до штатной синхронизации следуйте правилам ниже и не считайте спецификацию принятой или обновлённой.

### Структура страницы и UX-инварианты

- Активная страница собирается в `src/pages/landing/ui/LandingPage.tsx` из пяти полноэкранных слайдов: Hero, работы, отзывы, этапы, контакты.
- Сохраняйте дискретную слайдовую навигацию из `src/features/swipe-navigator/model/useDiscreteSwipe.ts`: колесо, вертикальный touch-жест, клавиатура, шапка и SideDots. Не заменяйте её обычной непрерывной прокруткой страницы.
- Все девять карточек этапов помещаются в viewport без внутренней вертикальной прокрутки. Одновременно открыт один пункт; повторное нажатие той же кнопки, клик по backdrop вне панели или Escape закрывают его. Если открыто мобильное меню, Escape сначала закрывает меню. Детали плавно появляются и исчезают через opacity поверх сетки, не сдвигая карточки; фон и панель также анимируются. Соблюдайте `prefers-reduced-motion`. При высоте viewport до 700 px детали показываются в центральной панели поверх затемнённой сетки. Карусель работ прокручивается горизонтально отдельно.
- Полосы прокрутки визуально скрыты; не отключайте реальную прокрутку областей, где она предусмотрена, включая горизонтальную прокрутку карусели работ.
- На мобильных экранах весь слайд «Работы» — заголовок, описание, обложка с подписями и контролы — помещается в viewport без внутренней вертикальной прокрутки. При нехватке высоты постер адаптируется по высоте; горизонтальная прокрутка карусели сохраняется отдельно.
- Работы показывают семь предоставленных обложек/визуальных концепций из `public/images/works/`. Для GitHub Pages собирайте URL с Vite `BASE_URL`; не возвращайте root-absolute `/images/...`, который даёт 404 в project subpath. Не придумывайте неподтверждённые результаты клиентов, награды или метрики.
- Этапы — девять карточек-аккордеонов в группах «До монтажа» и «Монтаж и постобработка». Съёмку выполняет клиент или его оператор; сайт может сообщать о помощи с подготовкой.
- Заголовок слайда этапов в RU — «ЧЕМ Я МОГУ ВАМ ПОМОЧЬ.», в EN — «WHAT I CAN HELP WITH.»; сохраняйте согласованный смысл переводов.
- Видео Hero загружается с публичного URL внешнего объектного хранилища: desktop-вариант на ширине больше 767 px, mobile — до 767 px. Пока не включён `prefers-reduced-motion: reduce`, видео остаётся смонтированным; воспроизводится только на первом слайде, при уходе ставится на паузу, а при возврате продолжается с сохранённой позиции. Не сохраняйте видео в `public/` и не добавляйте его в Git.

- Мобильное меню шапки закрывается повторным нажатием кнопки, кликом по backdrop или Escape. При Escape и выборе пункта навигации фокус возвращается на кнопку меню; таймеры закрытия и обработчики клавиатуры очищаются при смене состояния и размонтировании.
- Длительности анимаций и свойства переходов задаются motion-токенами `src/shared/styles/variables.css`. `will-change` используйте адресно для активных панелей, меню, полосок hamburger и наведённой обложки; не назначайте его всем карточкам. Соблюдайте `prefers-reduced-motion`, включая снятие compositor hints.

### Контент, ресурсы и требования

- Публичное позиционирование — видеомонтаж и постобработка. Отзывы показывают один RU/EN-моковый пример 5/5 с заметной меткой «не реальный отзыв»; не представляйте его как реальный. Локализуйте метку и ARIA-имя; реальные оценки/метрики публикуйте только с подтверждёнными материалами. Не возвращайте SMM.
- Язык интерфейса — RU/EN. Шрифты локальные в `public/fonts/`; цвета и типографика описаны в [docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md), архитектура — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Видео для сайта хранятся во внешнем объектном хранилище и подключаются по публичным URL. Не сохраняйте локальные видеофайлы в `public/` и не добавляйте видеофайлы в Git; локальные исходники в `Referens/` остаются неизменными и исключены из репозитория.
- Контактная кнопка пока ведёт на общий `https://t.me`. Не подставляйте выдуманный личный аккаунт или email; для замены нужен точный реквизит от владельца.
- По прямому разрешению владельца без CLI обновлены отзывы, этапы и BASE_URL-пути обложек; HG-0001 остаётся несинхронизированным. Не утверждайте формальное принятие или актуализацию; следующую формальную задачу ведите совместимым маршрутом.

### Проверки и публикация

- Команды и browser checks описаны в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Отдельного unit/e2e набора нет; type-check и сборки не заменяют браузерную проверку.
- Push в `main` запускает [GitHub Pages workflow](.github/workflows/deploy.yml) и публикует сайт. Считайте такой push production-действием; после отправки проверяйте workflow и Pages deployment для точного SHA, затем убедитесь, что опубликованная страница показывает изменённые разделы. Если запрос возвращает прежнее содержимое, повторите проверку свежим URL с cache-busting параметром, прежде чем считать деплой неуспешным.

<a id="маршрут-high-grade"></a>

## Маршрут High Grade

Используйте навыки High Grade из `.agents/skills/`:
- `highgrade-task`: уточнение задачи и выбор маршрута.
- `highgrade-spec`: создание/изменение спецификаций (SDD) перед реализацией.
- `highgrade-work`: реализация задач по утверждённым требованиям (TDD/BDD).
- `highgrade-planner`: координация цепочек зависимых задач.
- `highgrade-commit`: локальная фиксация готового этапа.
- `highgrade-clear`: актуализация документации и очистка временных артефактов.

<a id="границы-и-сохранение"></a>

## Границы и сохранение

- Референсы в `Referens/` являются исходными материалами и не изменяются.
- `Referens/` исключена из Git и может отсутствовать в клоне; локальные видеоформаты также игнорируются. Не обходите `.gitignore` через `git add -f`; перед коммитом проверяйте staged-файлы (`git diff --cached --name-only`) на отсутствие видео.
- `.work/` содержит временные материалы и промежуточные файлы; не включайте его в продуктовые коммиты.
- Активная Vite-точка входа — `index.html` → `src/main.tsx`; перед изменением корневых `styles/` и `scripts/` проверьте, что они подключены активной сборкой.
- Каталог `HighGrade-main/` содержит исходную библиотеку/дистрибутив High Grade и сохраняется без повреждений.
- Разработка ведётся в корне проекта (`index.html`, `src/`, `styles/`, `scripts/`, `docs/`, `specs/`).
- Документация пишется на русском языке. Машинные идентификаторы, теги и селекторы сохраняются без изменений.
